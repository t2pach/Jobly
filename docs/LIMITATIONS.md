# Ограничения и что нужно проверить до запуска

## 1. Интеграции

**«Работа России» (реализован, но не проверен на живых данных).**
Эндпоинты и параметры (`/vacancies`, `/vacancies/region/{код}`, `/vacancies/vacancy/{компания}/{id}`,
`text`, `offset`, `limit`, `experienceTo`) взяты из описания API портала. Из среды разработки внешний доступ был закрыт,
поэтому адаптер проверен только на тестовых фикстурах. Перед запуском проверьте на живом ответе:
- семантику `offset`: в статье на Хабре это номер страницы с 0, в примере портала `offset=1&limit=100`; адаптер передаёт номер страницы с 0;
- имена полей ответа (`job-name`, `salary_min`, `company.companycode`, `vac_url`, `creation-date`, `requirement.experience`)
  по схеме WADL (`/api/v1/vacancies/application.wadl`). Поля читаются через `.get`, поэтому ошибка схемы даст пустые значения, а не падение;
- условие использования открытых данных: показывать их **в неизменном виде**. Описание хранится как получено и
  не переписывается; не добавляйте «улучшение» текста вакансий.
- Зарплата `0` в источнике трактуется как «не указано».
- Источник не сообщает, до налогов зарплата или после (`salary_gross = None`), аналитика предупреждает об этом.

**hh.ru и SuperJob (адаптеры не реализованы).** Они возвращают статус `not_configured` / `degraded`, а не демо-данные.
По публикациям на Хабре hh.ru закрыл публичный API для соискателей с 15.12.2025, а API работодателя рассчитан на
HR-системы. Прежде чем писать адаптеры, подтвердите у платформ допустимость агрегации и показа вакансий в
стороннем сервисе, квоты и условия коммерческого использования (ТЗ, п. 2.1). Флаг `commercial_use_verified` везде `False`.

## 2. Не реализовано из ТЗ

- Загрузка и разбор резюме (PDF, DOCX), хранилище файлов (S3), версии резюме, адаптация резюме, экспорт в PDF/DOCX
  (таблицы `resume_document`, `resume_version` созданы, эндпоинтов нет).
- AI Gateway и всё, что на нём строится: AI-наставник (`/ai/chat`), AI-разбор требований вакансий, генерация roadmap.
  Сейчас оценка совпадения и письма детерминированные. Без структурированных навыков в вакансиях «Работы России»
  критерий навыков помечается как «нет данных» (разбор требований LLM-ом даст самый заметный прирост качества).
- Задачи roadmap (`roadmap_item` есть, эндпоинтов нет), уведомления (таблица есть, доставки и фоновых задач нет),
  Redis и очереди (BullMQ/Celery), восстановление пароля по email, Sentry, фронтенд на Next.js.
- Разделение резюме на подтверждённые и предполагаемые факты при автозаполнении профиля.

## 3. Безопасность и эксплуатация

- Лимитер запросов хранится в памяти процесса: при нескольких инстансах замените на Redis.
- JWT передаётся в заголовке Authorization (CSRF неприменим); срок жизни задаётся `JWT_TTL_MINUTES`, отзыва токенов нет.
- HTTPS, резервное копирование и мониторинг обеспечиваются инфраструктурой, в код не входят.
- Эндпоинты поиска асинхронные, а работа с БД синхронная (SQLAlchemy): для высокой нагрузки перейдите на асинхронный драйвер.
- Тесты выполнялись на SQLite. Миграция сгенерирована и применена на SQLite, SQL для PostgreSQL сформирован
  (`alembic upgrade head --sql`), но на живом PostgreSQL не запускалась.
- Персональные данные: нужны политика конфиденциальности, согласие на обработку, юридическая проверка 152-ФЗ
  (локализация, трансграничная передача, если AI-провайдер за пределами РФ). Код этого не заменяет.
